# Apps

Per-app notes for a rebuild. Anything needing a login is in
[04-secrets-and-logins.md](04-secrets-and-logins.md) instead.

## Editors

Three are installed, and all three keep settings in the same place, so the same
rule applies to each: `settings.json` and `snippets/` are tracked, everything
else in the profile directory is cache.

| Editor | Package | Config | Extensions |
|---|---|---|---|
| VS Code | `visual-studio-code-bin` (AUR) | `~/.config/Code/User/` | 33 |
| Cursor | `cursor` | `~/.config/Cursor/User/` | 0 |
| Antigravity | `antigravity-ide` (AUR) | `~/.config/Antigravity/User/` | — |
| VSCodium | `code-oss` | `~/.config/Code - OSS/User/` | 1 |

Extension lists are in `editors/*-extensions.txt`. Reinstall them with:

```bash
xargs -n1 code --install-extension < editors/vscode-extensions.txt
```

Swap `code` for `cursor` or `codium` as needed. Expect a few failures — some
extensions get unpublished or renamed, and the loop carries on past them.

The lists are generated by reading the extension **directories**, not by running
`code --list-extensions`. That CLI needs a display and silently returns nothing
when run over SSH or from a script, which produced an empty list the first time.

## Terminals

`kitty` is the daily driver. `alacritty` and `foot` are configured as backups —
foot in particular is worth keeping, since it starts when a GPU driver problem
stops kitty from starting.

## Shell

**zsh** is the login shell, with `starship` for the prompt. `fish` is installed
and configured but not the default.

`~/.config/zshrc.d/` holds three sourced fragments:

| File | What |
|---|---|
| `auto-Hypr.sh` | `exec start-hyprland` when logging in on TTY1 with no `$DISPLAY` |
| `dots-hyprland.zsh` | Applies the matugen-generated terminal colour sequences |
| `shortcuts.zsh` | Two zsh keybindings: `^H` backward-kill-word, `^Z` undo |

Note that Hyprland can start two ways here: greetd at boot, and `auto-Hypr.sh` if
you log in on TTY1 directly. The TTY1 path is the fallback for when greetd itself
is broken, which is exactly when you need it.

Change the login shell after a rebuild with `chsh -s /usr/bin/zsh`.

## Audio

PipeWire with WirePlumber, plus **EasyEffects** for output processing. Presets
are tracked in `~/.config/easyeffects/`.

Two local scripts in `~/.local/bin/` support this:

- `ee-jack-watch` — watches for headphone jack changes and switches the
  EasyEffects preset. Runs as the `ee-jack-watch.service` user unit.
- `ee-preset-cycle` — cycles presets by hand, bound to a key in the Hyprland
  config.

Enable the watcher after `install.sh`:

```bash
systemctl --user enable --now ee-jack-watch.service
```

Bluetooth audio works out of the box via `bluez` — the default sink on this
machine was a paired Bluetooth headset, which you will need to re-pair.

## Wallpapers

Two separate systems, which is why the layer patching in
[02-desktop.md](02-desktop.md) matters.

### Static

Three images in `wallpapers/static/`. Copy them to `~/Pictures/Wallpapers/` and
point matugen at one to regenerate the colour scheme:

```bash
mkdir -p ~/Pictures/Wallpapers
cp wallpapers/static/* ~/Pictures/Wallpapers/
matugen image ~/Pictures/Wallpapers/random_wallpaper.png
```

### Wallpaper Engine (animated)

Packages: `linux-wallpaperengine-git` (the renderer) and
`linux-wallpaper-engine-ux` (the GUI), both AUR.

The wallpapers themselves are Steam Workshop content — about **3 GB**, far too
much for this repo. What is tracked instead is the list of Workshop item IDs, in
`wallpapers/wallpaper-engine/workshop-items.md`: 42 items with titles and direct
Steam links, with a ★ on the one that was active.

To restore:

1. Install Steam and Wallpaper Engine (it is a paid app, and you need it owned on
   the account for the Workshop content to download).
2. Open each link in `workshop-items.md` and subscribe. Steam downloads into
   `~/.local/share/Steam/steamapps/workshop/content/431960/<id>`.
3. Copy the saved settings back:

```bash
cp wallpapers/wallpaper-engine/{active-wallpapers.json,settings.json,wallpaper-overrides.json} \
   ~/.config/"Linux Wallpaper Engine"/
```

`wallpaper-overrides.json` holds your per-wallpaper property tweaks and is the
part that is genuinely tedious to redo by hand.

Regenerate the manifest any time your subscriptions change:

```bash
./wallpapers/wallpaper-engine/generate-manifest.py
```

**Do not enable "launch on login" in the GUI.** It was turned off deliberately —
starting it before the Hyprland session is fully up produces a black screen
instead of a wallpaper. Start it from the Hyprland autostart config instead, so
it comes up after the compositor.

## Browsers

Chrome (both AUR `google-chrome` and the flatpak), Zen, and Thorium. Only the
`*-flags.conf` files are tracked — these carry the Wayland and GPU flags that
make Chromium behave under Hyprland. Profiles are login-bound and excluded; see
[04-secrets-and-logins.md](04-secrets-and-logins.md).
